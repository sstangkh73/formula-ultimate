# แผนงาน 003: เอกสารภาษาไทยแบบแยกไฟล์

วันที่: 2026-08-23
สถานะ: เสร็จสมบูรณ์

> ฉบับภาษาไทยของ `2026-08-23_003_thai-documentation-plan.md`

## วัตถุประสงค์

สร้างไฟล์ภาษาไทยแยกต่างหากให้กับ Markdown ภาษาอังกฤษทุกไฟล์ที่ดูแลใน
repository Formula Ultimate พร้อมบังคับใช้กฎเอกสารสองภาษาผ่านขั้นตอนทำงานและ
การทดสอบอัตโนมัติของ repository

## ขอบเขต

- ใช้ suffix `.th.md` สำหรับไฟล์คู่ภาษาไทย
- แปล Markdown ที่ดูแลอยู่ทั้งหมด ทั้งไฟล์กำกับงานระดับ root คำแนะนำ config
  เอกสารวิจัย/ฟิสิกส์ และแผน/ผลการทำงานย้อนหลังทุกชุด
- รักษา identifier สมการ คำสั่ง path หน่วย ค่าทดสอบ สถานะ และหลักฐานให้มี
  ความหมายเทียบเท่ากันระหว่างสองภาษา
- แก้ข้อกำหนด repository ให้การสร้างหรือแก้ Markdown ในอนาคตต้องสร้างหรือแก้
  ไฟล์ภาษาไทยคู่กันในงานเดียวกัน
- เพิ่มการทดสอบ repository contract ที่ตรวจพบไฟล์ภาษาไทยคู่กันที่ตกหล่น

## สิ่งที่ไม่ทำในงานนี้

- ไม่แปล source Python, TOML, YAML, Git metadata หรือ artifact ที่ generate
- ไม่แทนที่เอกสารภาษาอังกฤษด้วยเนื้อหาสองภาษาปนกัน
- ไม่เปลี่ยนพฤติกรรมฟิสิกส์หรือข้ออ้างทางการวิจัย
- ไม่อ้างว่า test ตรวจคุณภาพความหมายของคำแปลได้จากการมีไฟล์เพียงอย่างเดียว

## สิ่งส่งมอบที่วางแผนไว้

- ไฟล์ภาษาไทยคู่กันสำหรับ `.md` ภาษาอังกฤษที่ดูแลอยู่ทุกไฟล์
- แก้ `AGENTS.md`, `CONTRIBUTING.md`, `docs/WORK_PROTOCOL.md` และ `README.md`
  เพื่อระบุกฎสองภาษา
- automated test สำหรับบังคับ coverage ของไฟล์ภาษาไทยคู่กัน
- รายงานผล Work 003 แยกภาษาอังกฤษและภาษาไทย พร้อมหลักฐานที่ทำซ้ำได้

## กฎการตั้งชื่อ

```text
document.md          -> document.th.md
<slug>-plan.md       -> <slug>-plan.th.md
<slug>-result.md     -> <slug>-result.th.md
README.md            -> README.th.md
```

## ลำดับการทำงาน

1. สำรวจ Markdown ที่ดูแลอยู่นอก directory ที่ ignore หรือ generate
2. แปลเอกสารระดับ root และ config
3. แปลเอกสารวิจัย ฟิสิกส์ validation และ workflow
4. แปลแผนและผลการทำงานย้อนหลังโดยไม่เปลี่ยนความหมายเดิม
5. แก้ข้อกำหนด workflow สองภาษาและ navigation ของ repository
6. เพิ่มและรัน companion-coverage test
7. ตรวจ identifier สมการ path คำสั่ง หน่วย และค่าทดสอบให้ตรงกัน
8. เขียนรายงานผลแยกภาษาอังกฤษและภาษาไทย
9. รัน test ทั้งหมด compilation และ staged-diff check แล้ว commit/push

## แผนการตรวจสอบ

- แจกแจง Markdown ภาษาอังกฤษที่ดูแลอยู่ทั้งหมด และตรวจว่ามี `.th.md` คู่กัน
- ตรวจว่าไฟล์ภาษาไทยทุกไฟล์ไม่ว่างและระบุไฟล์ต้นฉบับภาษาอังกฤษ
- รัน Python test suite ทั้งหมด
- รัน Python compilation และ `git diff --cached --check`
- ตรวจ GitHub Actions หลัง push

## เกณฑ์สำเร็จ

- Markdown ภาษาอังกฤษทุกไฟล์ที่ดูแลอยู่มีไฟล์ภาษาไทยแยกคู่กัน
- หากไฟล์ภาษาไทยตกหล่น repository-contract test ต้อง fail
- การจับคู่ plan/result ยังถูกต้องในทั้งสองภาษา
- ไม่มีการเปลี่ยนพฤติกรรมฟิสิกส์ Python ในงานนี้
- test suite ในเครื่องและ GitHub Actions ผ่าน

## ความเสี่ยงและการควบคุม

- คำแปลคลาดเคลื่อน: รักษา identifier/สมการตามต้นฉบับและเชื่อมไฟล์ภาษาไทยกับ
  source ทุกไฟล์
- การตั้งชื่อกำกวม: ใช้มาตรฐาน `.th.md` เดียวทั้ง repository
- ภาระดูแลเพิ่ม: บังคับ coverage อัตโนมัติและให้แก้ทั้งคู่ในงานเดียวกัน
- ความมั่นใจเกินหลักฐาน: automated test พิสูจน์ coverage และโครงสร้าง ไม่ได้
  พิสูจน์ความสมบูรณ์ของความหมาย คำแปลยังต้องผ่านการ review
