## วัตถุประสงค์

Milestone 4 ของ `auto-loop/GOAL.md`: วางชิ้นส่วนใบทุกชิ้นของต้นไม้นามธรรมจาก Work 150 ในพิกัดยานยนต์
และแปลง attachment ทุกตัวของ Work 150 เป็น interface ที่วางแผนไว้ ซึ่งมีการสัมผัสแบบหน้าปลายแบน (cap-to-cap)
ที่วัดได้และไม่มีการทะลุกัน งานนี้เป็นการวางแผนด้วย Python ล้วน การสร้าง CAD จากโปรแกรมที่วางแผนแล้วเป็นงานถัดไป

## ขอบเขต

- โมดูลใหม่ `src/formula_ultimate/hierarchy/layout.py`:
  - `layout(tree, config)` คืนโปรแกรมที่วางตำแหน่งแล้วของแต่ละใบ (`leaf_program` + `placement_transforms`
    ของ Work 151) และ interface ที่วางแผนไว้
  - ขั้นตอน (ประกาศไว้ ขับด้วย seed ไม่มีแคตตาล็อกชิ้นส่วน): วาง anchor leaf ของ root ที่จุดกำเนิด แล้ว
    เรียกซ้ำแบบ depth-first: วาง anchor child ของ assembly ก่อน แล้วสำหรับ satellite child แต่ละตัว ให้วาง
    anchor leaf ของ satellite บนหน้าปลายแบนของใบที่วางแล้วใน subtree ของ anchor child แล้วเรียกซ้ำเข้า satellite
    เป้าหมายของ attachment ถูกเลือกใหม่ตอนวางผัง (เป้าหมายจาก decomposition เป็นใบสุ่มใน anchor subtree เดียวกัน
    การเชื่อมต่อจึงไม่เปลี่ยน)
  - กฎการสัมผัส: ใบทั้งสองอยู่ร่วมแกนบนแกนของหน้าปลายร่วม หน้าปลายอยู่ในระนาบเดียวกัน และแผ่นวงกลมของหน้าปลาย
    ที่เล็กกว่า (`outer_radius + |offset|`) อยู่ภายใน `inscribed_radius` ของหน้าปลายที่ใหญ่กว่า ลบด้วย linear
    tessellation tolerance ของมัน ถ้าไม่พอดีทั้งสองทิศ จะย่อใบต้นทาง (สุ่มรูปร่างเดิมของใบนั้น ความยาวเล็กลง)
    แต่ไม่ต่ำกว่า `min_leaf_length_m`
  - กฎการชน: กล่องแนวแกนแบบอนุรักษ์ของทุกใบ (`outer_radius` ขวางแกน, `[0, h]` ตามแกน) ต้องไม่ซ้อนทับภายใน
    กับกล่องของใบอื่นใด การแตะกันยอมได้ กล่องของ mesh ที่วัดจริงอยู่ภายในกล่องเหล่านี้ การทดสอบการทะลุของ
    acceptance จึงไม่มีคู่ที่ซ้อนทับให้ตรวจ
  - `layout_problems(result)` ตรวจซ้ำความไม่ซ้อนทับของกล่อง การสัมผัสหน้าปลาย และการบรรจุ จากโปรแกรมที่วาง
    แล้วด้วย `transform_points`
- เทสต์ใหม่ `tests/test_hierarchy_layout.py`

## เกณฑ์ความสำเร็จ

- seed 11, 23, 37 และ seed อื่นอีกชุดหนึ่ง วางผังได้ทุกใบโดยไม่ล้มเหลว และกำหนดผลได้แน่นอน
- `layout_problems` ว่าง: กล่องไม่ซ้อนทับภายในเป็นคู่ ทุก interface ร่วมแกน หน้าปลายร่วมระนาบ และหน้าปลายที่เล็กกว่า
  อยู่ในแผ่นวงในของหน้าปลายที่ใหญ่กว่า
- ลูกของทุก assembly เชื่อมต่อกันผ่าน interface ที่วางแผนไว้
- ผังที่จงใจให้ซ้อนทับหรือแยกห่าง ถูกรายงานโดย `layout_problems` (เทสต์พิสูจน์ความผิด)

## ความเสี่ยง

- ความแออัด: subtree ที่โตขึ้นอาจหาหน้าปลายว่างไม่ได้ ทำให้ล้มเหลว ซึ่งจะ raise เป็น `LayoutFailure` ไม่ซ่อนไว้
- การย่อใบต้นทางทำให้บางใบเล็กลง ช่วงขนาดที่วัดจริงยังต้องตรวจหลังสร้าง CAD
- ความไม่ซ้อนทับของกล่องเป็นแบบอนุรักษ์และทำให้ยานยนต์โปร่ง เป็นทางเลือกการแทนข้อมูล ไม่ใช่ข้ออ้างการออกแบบ
