## Bug report

- **Symptom.** After the Work 142 commit, `git status` showed `config/development/vehicle_part_resolution_v1.json` as modified although no one had edited it. The change was one added key, `"upgraded_definitions": []`.
- **Root cause.** Work 142 gave the generator an `--upgrade` mode and wrote the new key unconditionally, so a plain regeneration no longer produced the Work 141 declaration. Since the Work 141 result hashes that exact file through `config_sha256` and `protocol_sha256`, the recorded result had quietly stopped being re-derivable from the repository.
- **Fix.** The key is written only for an upgrade run. The Work 141 declaration was restored from the repository rather than rewritten to match the generator, because rewriting it would have invalidated a recorded hash to make a tool look right.
- **Regression.** Regenerating both declarations now leaves the working tree clean: `git add` of both files stages nothing.

**Rule this leaves behind.** A change to a generator must keep every declaration it has already produced regenerable. Adding a field to new outputs is fine; adding it to old ones is a silent break of a recorded identity.
