# แผน Work 106: การค้นพบชิ้นส่วนละเอียดไปจนถึงรถทั้งคัน

ต้นฉบับภาษาอังกฤษ: `2026-09-07_106_detailed-part-to-vehicle-roadmap-plan.md`

วันที่: 2026-09-07 (Asia/Bangkok)

Status: Completed

## วัตถุประสงค์

อ่านการพัฒนาและหลักฐานล่าสุด แล้วกำหนดเส้นทางที่ลงมือทำได้ไปสู่เรขาคณิตรถครบทั้งคัน รวมชิ้นส่วนภายในและรายละเอียดการยึด โดยไม่จำกัดการค้นพบอยู่กับรูปทรงชิ้นส่วนที่คุ้นเคยหรือโครงสร้างรถแบบเดิม เสรีภาพของรูปทรงยังอยู่ภายใต้ฟิสิกส์ เงื่อนไขโจทย์ และขอบเขตหลักฐานที่ประกาศชัดเจน

## ขอบเขตและข้อมูลตั้งต้น

งานนี้เป็นการวางแผนและเขียนเอกสาร ไม่ใช่การสร้างตัวแก้ฟิสิกส์ในอนาคตหรือทดลองรถใหม่ ตรวจ Work 105 ที่ commit `ea70f5f`, protocol กำกับจาก Work 104, หลักฐาน CAD และการประกอบก่อนหน้า และโค้ด morphology/network/intake ปัจจุบัน เก็บบันทึกเก่าไว้ตามเดิม ใช้เอกสารเทคนิคจากแหล่งต้นทางเพื่อกำหนดขอบเขตตัวเลือกโครงสร้างพื้นฐานเท่านั้น ไม่ติดตั้งหรือเลือก backend ใช้งานจริงโดยยังไม่ผ่าน benchmark

## แนวทางละเอียด

1. แยกสิ่งที่พิสูจน์แล้วด้านเรขาคณิต ฟิสิกส์ลดรูป ความใหม่เชิงเหตุผล และความพร้อมของรถ
2. นิยามรายละเอียดเรขาคณิตครบถ้วนแยกจากความละเอียดการจำลอง ระบุบริเวณวัสดุ ช่องว่าง รอยต่อ อุปกรณ์ภายใน tolerance การนับเนื้อวัสดุ และการถ่ายโอนแบบจำลองหลายระดับ
3. วางโครงสร้าง representation และ evaluator ที่ขยายได้ การค้นหาชิ้นส่วนควบคู่รถ การบันทึกต้นทุน การพยายามหักล้าง และเกณฑ์เลื่อนระดับหลักฐาน
4. แบ่งเป็นงานย่อยขอบเขตชัดเจน พร้อม dependency, artifact, test, หลักฐานจบงาน และข้อกำหนดงานถัดไปที่นำไปพัฒนาได้
5. ระบุความไม่แน่นอนในการวิจัย คอขวดคำนวณ ฟิสิกส์ที่ยังไม่รองรับ การตรวจสอบกับฮาร์ดแวร์ และสิ่งที่ไม่ทำ
6. ตรวจความครบถ้วนสองภาษาและลิงก์ใน repository ทบทวนให้ตรง protocol กำกับ แล้ว commit เฉพาะไฟล์งานนี้ทันทีหลังตรวจผ่าน

## การตรวจสอบ

- `python -m unittest tests.test_repository_contract -v` ต้องจบด้วย exit `0`
- ตรวจเอกสารแบบอ่านอย่างเดียว: ไฟล์คู่ ชื่อต้นฉบับในภาษาไทย ลิงก์ Markdown ภายใน หมายเลขหัวข้อ roadmap หมายเลขงานที่เสนอ และค่าทางเทคนิคที่ตรงกัน บันทึกคำสั่งและผลในบันทึกผล
- ตรวจด้วยการอ่าน: ทุกงานอนาคตมี dependency และหลักฐานจบที่วัดได้ ไม่เรียกรูปทรงหรือฟิสิกส์ที่ยังไม่รองรับว่าเป็นไปไม่ได้ทางฟิสิกส์ ไม่ตัดการปรับรูปทรงต่อเนื่องออกเพียงเพราะกราฟไม่ใหม่ และไม่บังคับ exploratory integration ให้ใช้เฉพาะชิ้นส่วนที่ผ่านเดี่ยวแล้ว
- `git diff --check` และ `git diff --cached --check` ต้อง exit `0`; ตรวจรายชื่อไฟล์ staged เฉพาะขอบเขตก่อน commit และตรวจ commit ใหม่หลังทำสำเร็จ

## เกณฑ์สำเร็จ

roadmap สองภาษาอธิบายเส้นทางเฉพาะเจาะจงจากการสาธิตที่ยังจำกัดไปสู่ชิ้นส่วนละเอียดและ candidate รถทั้งคันที่เชื่อมโยงฟิสิกส์ พร้อมวิธีพยายามหักล้างแต่ละหมุดหมาย ระบุงานพัฒนาถัดไปทันที และไม่อ้างว่าเอกสาร การสร้าง CAD สำเร็จ หรือ Level-0 simulation ยืนยันรถจริงได้ commit ทั้งหกไฟล์ร่วมกัน

## ความเสี่ยงและสิ่งที่ไม่ทำ

ความเสี่ยง: สัญญาเกินจริงเรื่องรูปทรงใดก็ได้ มองข้อจำกัดซอฟต์แวร์เป็นกฎฟิสิกส์ วนทำแต่ระบบตรวจรับ ใช้รายละเอียดภาพแทนเรขาคณิตที่ส่งผลจริง และสับสนผลตรวจเก่ากับ test ที่เพิ่งรัน ลดความเสี่ยงด้วยแผนที่ขอบเขตการรองรับ หมุดหมาย geometry-to-field ตั้งแต่ต้น สถานะหลักฐานแยกมิติ และระบุที่มาของผลย้อนหลัง

สิ่งที่ไม่ทำ: ลงมือสร้างทั้ง roadmap ในรอบนี้; กำหนดจำนวนล้อ รูปร่างตัวถัง powertrain หรือน็อตมาตรฐานเป็นข้อบังคับ; พิสูจน์ความใหม่เทียบ prior art ภายนอก; ซื้อหรือติดตั้งเครื่องมือ; ทดลองฮาร์ดแวร์; push หรือเขียนประวัติ Git ใหม่; เปลี่ยนแผนเก่าให้ดูเหมือนวางลำดับใหม่ไว้แต่แรก
