# Lateral/Yaw and Load-Transfer Model

Thai companion: `LATERAL_YAW_LOAD_TRANSFER_MODEL.th.md`

## Status and claim boundary

Work 016 implements `work016-planar-v1`, a deterministic Level-0 planar
rigid-body selection model. It couples contact kinematics, a linear
slip-angle force request, Work 011 combined tyre-force saturation,
quasi-static longitudinal/lateral load transfer, and explicit planar state
integration.

Passing this model is not physical validation, tyre calibration, safety
evidence, or a real lap-time claim.

## Topology contract

`PlanarVehicle` accepts an ordered tuple of `PlanarContact` values. Each contact
declares:

- unique ID and arbitrary body-frame position `(x_i, y_i)` in metres;
- baseline normal load in newtons;
- steer angle in radians;
- cornering stiffness in newtons per radian;
- requested longitudinal force in newtons; and
- Work 011 longitudinal/lateral friction coefficients.

The implementation does not require four wheels, paired sides, or two axles.
The baseline loads must sum to `m*g` and have zero pitch/roll moment. The active
contact geometry must have enough independent position information to resolve
vertical, pitch, and roll equilibrium; rank-deficient layouts return
`invalid`.

## Contact kinematics and requested force

For body velocity `(u, v)`, yaw rate `r`, contact position `(x_i, y_i)`, and
steer angle `delta_i`:

```text
Vx_body_i = u - r*y_i
Vy_body_i = v + r*x_i

Vx_local_i =  cos(delta_i)*Vx_body_i + sin(delta_i)*Vy_body_i
Vy_local_i = -sin(delta_i)*Vx_body_i + cos(delta_i)*Vy_body_i

alpha_i = atan2(Vy_local_i,
                max(abs(Vx_local_i), speed_regularization))
Fy_requested_i = -C_alpha_i * alpha_i
```

The declared `Fx_requested_i` and calculated `Fy_requested_i` pass unchanged to
`resolve_tyre_force`. Work 011 radially projects over-limit requests onto the
declared friction circle/ellipse. Each `PlanarContactResult` retains local
velocity, slip angle, requested and applied force, utilization, saturation,
body-frame force, and yaw moment.

The linear slip law is a request model only. It has no relaxation length,
temperature, camber, pressure, wear, or empirical nonlinear force curve.

## Quasi-static load transfer

At a declared body-frame inertial acceleration `(a_x, a_y)`, normal loads must
satisfy:

```text
sum(Fz_i)       = m*g
sum(x_i*Fz_i)   = -m*a_x*h
sum(y_i*Fz_i)   = -m*a_y*h
```

Among all solutions, the solver chooses the minimum Euclidean change from the
declared baseline-load vector. If `A` contains the three constraint rows, the
projection is:

```text
Fz = Fz_baseline + A^T * (A*A^T)^-1 * (b - A*Fz_baseline)
```

This makes the distribution deterministic for any full-rank contact topology.
Negative projected normal load is reported as contact lift and returns
`invalid`; it is never clipped to zero. The raw projected loads and equilibrium
residuals remain observable.

## Coupled solve

Tyre capacity depends on normal load, while load transfer depends on the forces
generated by those tyres. `step_planar_dynamics` therefore runs a deterministic
fixed-point iteration:

1. start from zero acceleration;
2. project normal loads at the acceleration guess;
3. resolve every contact's combined force;
4. calculate `a_x = sum(Fx)/m` and `a_y = sum(Fy)/m`;
5. compare with the guess, then update it by the declared relaxation factor;
6. stop only inside absolute/relative acceleration tolerance.

The default limit is 64 iterations and the default relaxation factor is `0.5`.
The result reports iterations and convergence. Rank deficiency, contact lift,
non-finite arithmetic, Work 011 numerical failure, insufficient iteration
budget, or a balance outside declared tolerance returns `invalid` with the
state unchanged.

## Planar balances and integration

Applied local forces are rotated into the body frame. Total force and moment
define:

```text
m*(du/dt - r*v) = sum(Fx_body_i)
m*(dv/dt + r*u) = sum(Fy_body_i)
I_z*dr/dt       = sum(x_i*Fy_body_i - y_i*Fx_body_i)
```

One step uses explicit Euler derivatives evaluated at the start state:

```text
du/dt = a_x + r*v
dv/dt = a_y - r*u
dx/dt = cos(heading)*u - sin(heading)*v
dy/dt = sin(heading)*u + cos(heading)*v
dheading/dt = r
```

The result exposes vertical-force, pitch-moment, roll-moment, longitudinal-force,
lateral-force, and yaw-moment residuals. These residuals establish internal
accounting only; they do not establish model fidelity.

## Reference evidence

`scripts/validate_lateral.py` checks:

- steady straight motion: one iteration and all six residuals exactly zero;
- positive front steering: positive lateral and yaw acceleration;
- analytical `a_x=2 m/s^2`, `a_y=3 m/s^2` load-transfer directions and zero
  vertical/pitch/roll residuals;
- combined-force saturation with applied utilization no greater than `1`; and
- exact replay plus an intentionally insufficient iteration budget returning
  `invalid`.

The test suite also covers a three-contact delta layout, rank-deficient
geometry, contact lift without clipping, dynamic balances, invalid contracts,
and deterministic replay.

## Limitations and follow-up boundary

- No heave, pitch, roll dynamics, suspension travel, compliance, camber,
  relaxation length, contact-patch transients, or road roughness.
- No aerodynamic force or aerodynamic load transfer; Work 017 owns that scope.
- No mechanical/regen braking-system or suspension model; Work 018 owns that
  scope.
- No calibrated tyre data, real racing line, sector geometry coupling, or
  physical-validation claim.
