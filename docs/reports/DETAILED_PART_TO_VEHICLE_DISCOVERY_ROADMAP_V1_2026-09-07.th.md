## 1. จุดหมายและเอกสารกำกับ

สร้างระบบที่สร้างรถแข่งครบทั้งคัน รวมเรขาคณิตภายในที่ทำหน้าที่จริงและรายละเอียดการประกอบลงไปถึงระดับการยึดชิ้นส่วน โดยค้นหารูปทรง การกระจายวัสดุ รอยต่อ สถาปัตยกรรม และการควบคุมร่วมกัน ไม่ใช่เพียงเลือกชิ้นส่วนที่คุ้นเคยจากแค็ตตาล็อก ปรับขนาดรถสำเร็จรูป หรือทำ CAD ละเอียดมาตกแต่ง simulator อุดมคติภายหลัง

[Protocol จาก Work 104](../contracts/WHOLE_VEHICLE_TECHNOLOGY_DISCOVERY_PROTOCOL_V1_2026-09-06.th.md) ยังคงเป็นข้อกำกับเรื่องฟิสิกส์ การแข่ง พลังงาน ความเป็นธรรม และการเลื่อนระดับหลักฐาน roadmap นี้ขยายรายละเอียดลำดับพัฒนาหลัง Work 105 ไม่เขียนผลย้อนหลังใหม่และไม่เปลี่ยนโจทย์ภายนอก โดยเฉพาะข้อเสนอท้าย Work 105 ที่ให้หาชิ้นส่วนผ่านเดี่ยวเพิ่มก่อน ไม่ใช่เงื่อนไขสากลว่าต้องผ่านเดี่ยวครบจึงจะทดลองรวมระบบได้ การออกแบบควบคู่เชิงสำรวจทำได้ก่อน แต่คำกล่าวอ้างที่เข้มขึ้นยังต้องมีหลักฐานเพียงพอสำหรับสภาพการประกอบจริง

เสรีภาพที่ต้องการคือไม่ถูกล็อกด้วยแค็ตตาล็อกรูปทรงหรือโครงสร้างรถที่กำหนดไว้ ไม่ใช่เสรีภาพจากกฎอนุรักษ์หรือเงื่อนไขโจทย์ที่ประกาศ ไม่มีอัลกอริทึมที่ใช้ทรัพยากรจำกัดใดแทนและประเมินรูปทรงที่เป็นไปได้ทางคณิตศาสตร์ทั้งหมดได้ เป้าหมายเชิงวิศวกรรมคือพื้นที่ค้นหาที่ขยายได้ ควบคุมความละเอียดได้ และแสดงช่องว่างการรองรับอย่างชัดเจน ไม่ใช่อ้างว่าแทนรูปทรงได้ไร้ข้อจำกัดโดยแท้จริง

ตัวบรรยายกราฟของ Work 105 ละ terminal coloring, ทิศทาง และจำนวนขอบขนานไว้อย่างชัดเจน จำนวนกลไกศูนย์จึงไม่ได้พิสูจน์ว่าการปรับรูปทรงโดย topology คงเดิมค้นพบหน้าที่ที่มีประโยชน์ไม่ได้ หรือรูปทรงไม่คุ้นเคยทำงานไม่ได้ การศึกษาใหม่ต้องแยกความใหม่ของเรขาคณิต ความต่างของหน้าที่ที่มีเหตุรองรับ ผลสมรรถนะที่ดีขึ้น และความใหม่เทียบ prior art ภายนอก การตอบสนองที่แย่ลงไม่ใช่การปรับปรุง แม้ค่าสัมบูรณ์ของความต่างจะมาก

สะพานหลักที่ยังขาดคือ **เรขาคณิตเนื้อวัสดุ/ช่องว่างที่สร้างขึ้น → สนามฟิสิกส์และ contact ที่มาจากเรขาคณิต → ชุดประกอบที่ทำงาน → หลักฐานรถทั้งคันที่เชื่อมโยงระบบ** การเพิ่ม intake ที่ตรวจแต่รายการอีกชุดไม่ได้สร้างสะพานนี้

## 3. นิยามรายละเอียดครบถ้วน

สำหรับ candidate ดิจิทัลขั้นสุดท้าย ทุกสิ่งที่จำเป็นทางกายภาพต้องมีเรขาคณิตและวัสดุที่ชี้ตัวตนได้ หรือมีรายการช่องว่างที่ยังไม่ทราบอย่างเปิดเผย เรขาคณิตขั้นสุดท้ายที่เลื่อนระดับแล้วต้องไม่มีแหล่งแรง กำลัง ความเย็น การรับรู้ หรือการยึดอุดมคติที่ไม่มีคำอธิบายทางกายภาพ

กำหนดความครบถ้วนตามหน้าที่ ไม่ใช่บังคับรายการชิ้นส่วนรถแบบเดิม:

- บริเวณรับแรง โพรง ทางเดินภายใน สมาชิกที่เคลื่อนที่ และส่วนรองรับ
- การทำให้การยึดและข้อจำกัดการเคลื่อนที่เกิดขึ้นจริง: เกลียว พื้นที่ยึดติด การสวมอัด จุดเชื่อมยืดหยุ่น การขัดล็อก หรือวิธีอื่นที่มีแบบจำลอง ตามที่แบบนั้นต้องใช้
- อุปกรณ์ภายในสำหรับเก็บ แปลง และส่งพลังงาน รวมภาชนะกักเก็บ ฉนวน และความสูญเสีย
- ปฏิสัมพันธ์กับพื้น/สิ่งแวดล้อม การควบคุมทิศทางและหยุด โดยไม่กำหนดล้อ เพลา หรือชุดคันชักบังคับเลี้ยวล่วงหน้า
- ทางถ่ายเทความร้อน พื้นผิวแลกเปลี่ยน ทางของไหล และการซีลเมื่อจำเป็น
- ฮาร์ดแวร์ actuator และ sensor สายไฟหรือเส้นทางสัญญาณทางกายภาพชนิดอื่น แหล่งจ่าย จุดติดตั้ง และสมมติฐาน latency
- tolerance, สถานะประกอบ, preload, การหล่อลื่นเมื่อจำเป็น, พื้นที่เข้าถึงเครื่องมือ และเงื่อนไขซ่อม/เปลี่ยนเมื่อโจทย์กำหนด

ถ้าเลือกข้อต่อเกลียว สุดท้ายต้องมีแนวเกลียว รูปร่างด้านข้างและรากเกลียว ระยะขบ รูปทรงคู่ประกบ ระยะเผื่อ และผิวรองรับจริง ถ้าเป็นจุดเชื่อมยืดหยุ่นที่รวมเป็นเนื้อเดียว อาจไม่ต้องมีสิ่งเหล่านี้ แต่ต้องมีหลักฐานการเสียรูป ความล้า การผลิต และความเสียหายของวิธีนั้นเอง อนุญาตชิ้นส่วนมาตรฐานที่ซื้อมาได้ถ้าการศึกษานั้นอนุญาต แต่ต้องแทนเรขาคณิต คุณสมบัติ และที่มา และไม่นับว่าเป็นสิ่งที่ระบบสร้างค้นพบ

ทุกบริเวณวัสดุต้องบันทึกตัวตน เรขาคณิต กฎวัสดุและที่มา การเป็นเจ้าของเนื้อวัสดุ ตำแหน่ง tolerance หน้าที่ที่เกี่ยวข้อง และหลักฐานอ้างอิง ทุกหน้าที่ที่ต้องมีต้องไล่เส้นทางทางกายภาพผ่านบริเวณเหล่านี้ได้ครบ รายชื่อหน้าที่ที่ไม่มีเนื้อวัสดุรองรับยังไม่ครบถ้วน

## 4. เสรีภาพ ขอบเขต และการควบคุมอคติ

ไม่กำหนดเงาร่าง ความสมมาตร จำนวนล้อ จำนวนเพลา จำนวนชิ้นส่วน หน้าตัดมาตรฐาน ตระกูล powertrain หรือหนึ่งชิ้นต่อหนึ่งหน้าที่ เพียงเพราะคุ้นเคย และไม่ให้รางวัลความแปลกตาแทนสมรรถนะ ถ้ารูปทรงคล้ายของเดิมชนะด้วยการเปรียบเทียบที่เป็นธรรมก็ยอมรับได้

แยกที่มาของข้อจำกัดสี่ประเภท:

| ข้อจำกัด | วิธีปฏิบัติ |
|---|---|
| กฎฟิสิกส์หรือขอบเขตที่ข้อมูลวัสดุวัดมารองรับ | บังคับสำหรับคำกล่าวอ้างในโดเมนฟิสิกส์นั้น |
| โจทย์แข่ง พลังงาน สิ่งแวดล้อม และความปลอดภัยภายนอก | ล็อกก่อนการเปรียบเทียบที่รับเป็นหลักฐาน ไม่แอบเปลี่ยนให้เข้าข้าง candidate |
| ความละเอียดเชิงตัวเลข ฟิสิกส์ที่รองรับ geometry kernel และงบคำนวณ | ประกาศเป็นขอบเขตการรองรับ การประเมินไม่ได้ไม่ใช่หลักฐานว่าเป็นไปไม่ได้ทางฟิสิกส์ |
| วิธีผลิต วัตถุดิบที่มี หรือขั้นตอนประกอบ | ระบุเป็นเงื่อนไขตามช่วงงาน เรขาคณิตสำรวจยังมีสถานะการผลิตไม่ทราบได้ |

ขนาด feature ต่ำสุด ขอบเขตโดเมน และเพดานความซับซ้อนเป็นตัวเลือกคำนวณที่จำเป็น ต้องลงทะเบียนเหตุผลและศึกษาผลของการขยายขอบเขต/เพิ่มความละเอียด ไม่ยกให้เป็นกฎสากล รายงานแยกว่าข้อเสนอใดถูกปฏิเสธเพราะ representation, meshing, ละเมิดฟิสิกส์, งบหมด หรือการผลิต

ตัวอย่างชิ้นส่วนที่รู้จักเป็นชุดทดสอบความถูกต้องและ baseline ที่ปรับให้ดีแล้ว ไม่ใช่ genome ที่อนุญาตเพียงชุดเดียว ใส่ชุดทดสอบไม่คุ้นเคยที่มีทางรับแรงโค้ง โพรงแตกแขนง สนามวัสดุไม่สมมาตร และบริเวณหลายหน้าที่ โดยรายการตัวอย่างนี้ก็ไม่ใช่ขอบเขตตายตัวของการค้นหาในอนาคต

ใช้ข้อกำหนดข้อมูลเชิงพื้นที่ร่วมกัน รองรับ generator หลาย backend ไม่ใช้รายชื่อชิ้นส่วนสำเร็จรูปเป็นภาษาสากล

| ชั้นข้อมูล | สิ่งที่เสนอให้มี | พฤติกรรมที่ต้องได้ |

| แบบจำลองฟิสิกส์ | mesh, กฎวัสดุ, contact, แบบลดรูป, ประวัติเงื่อนไขขอบเขต | มาจาก candidate revision เดียวกัน มีขอบเขตการใช้และความคลาดเคลื่อนเชิงตัวเลข |
| ชุดหลักฐาน | ตัวตน genome, geometry, mesh, solver, materials, loads, environment, controller และ accounting | เมื่อ input ที่ส่งผลเปลี่ยน หลักฐานที่พึ่งพาต้องหมดอายุ เว้นแต่มีเหตุผลรองรับการถ่ายโอนชัดเจน |

เริ่มจากใช้ B-rep export/inspection ที่มีหลักฐานแล้ว เพิ่มเส้นทาง implicit/adaptive-volume เพื่อเพิ่ม/ลบเนื้อวัสดุและเปลี่ยน topology โดยไม่ต้องไล่รายชื่อรูปทรงเครื่องกล ไม่อ้างว่าการแปลง implicit candidate ทุกแบบเป็น B-rep ปิดสนิทแก้ได้แล้ว การแปลงเป็น adapter ที่ต้องทดสอบแยก และ export ที่ไม่รองรับต้องแสดงสถานะไว้ การประเมินตรงจาก mesh ใช้เชิงสำรวจได้เมื่อบันทึกความคลาดเคลื่อนเรขาคณิตและรอยต่อวัสดุ แต่ชิ้นงานส่งมอบทางวิศวกรรมขั้นสุดท้ายต้องผ่านข้อกำหนด export/inspection ที่ประกาศ

แยกตัวตนสามแบบ: ตัวตนโปรแกรมสร้างแบบตรงกันทุกข้อมูล ความเทียบเท่าทางเรขาคณิตภายใน tolerance ที่ประกาศ และความเทียบเท่าของหน้าที่ภายใต้โจทย์ที่ประกาศ โปรแกรมต่างกันอาจสร้างรูปทรงเทียบเท่ากัน ส่วน topology ของกราฟเท่ากันก็อาจให้ฟิสิกส์ที่มีประโยชน์ต่างกัน

### 5.1. สิ่งที่ generator เปลี่ยนได้จริง

candidate อาจแทนขอบเขต implicit ต่อเนื่องที่สุ่มค่าบนกริดเชิงพื้นที่ปรับความละเอียดได้ ให้ด้านหนึ่งมีวัสดุและอีกด้านเป็นช่องว่าง กริดนี้เป็นฐานคำนวณ ไม่ใช่คำสั่งให้ชิ้นส่วนต้องเป็นบล็อก เพิ่มความละเอียดขอบเขตจน geometric error ผ่าน tolerance ตามสเกล feature ที่ลงทะเบียน อีกทางคือวิวัฒน์ข้อมูลควบคุมผิว free-form และโปรแกรม B-rep features ต้องทดสอบความสอดคล้องในส่วนที่ representations รองรับร่วมกัน ไม่สมมติว่าใช้แทนกันได้ทันที

mutations ของ candidate ต้องค่อย ๆ ครอบคลุมการเลื่อนขอบเขต ความหนาแปรตามพื้นที่ การสร้างและเดินทางโพรง การแตกแขนงเฉพาะที่ การกระจายวัสดุใหม่ ย้าย interface แยก/รวม part และจัดชุดประกอบใหม่ จำกัดวัสดุผสมหรือ gradient ตามกฎ constitutive/กระบวนการที่ประกาศรองรับ ไม่ interpolate คุณสมบัติตามใจจนประดิษฐ์ super-material ที่ทำจริงไม่ได้ ความเรียบผิวและรัศมีต่ำสุดเป็นพารามิเตอร์ trial/process/numerical ไม่ใช่ข้อบังคับให้ output ทุกชิ้นคล้าย primitive ที่รู้จัก

ใช้ลำดับชั้นย้อนที่มาได้จากรถ ไปกลุ่มหน้าที่ ชิ้นส่วนทางกายภาพ บริเวณวัสดุ และ feature โดยให้หลายกลุ่มอ้างบริเวณเดียวกันได้โดยไม่นับเนื้อซ้ำ hierarchy การประกอบเป็นการจัดข้อมูล ไม่ใช่กายวิภาครถตายตัว features ย่อยอาจเป็นรากเกลียว ผิวซีล หรือผิว contact ที่สร้างใหม่ เฉพาะเมื่อ candidate นั้นจำเป็นต้องใช้ เก็บ spatial resolution และ approximation error กับแต่ละ representation เพื่อไม่ให้ feature เล็กแต่สำคัญทางกลหายไปอย่างเงียบ ๆ

ทดสอบความเปิดด้วยการเทียบ template ชิ้นส่วนชื่อคงที่ member grammar เดิม และเส้นทาง spatial-material ภายใต้ functional task เดียวกันและทรัพยากรเท่ากัน วัดความหลากหลาย geometry/function ที่เข้าถึงได้และประโยชน์ที่ตรวจแล้ว ไม่ใช่นับ operators อย่างเดียว มีโจทย์ลงทะเบียนล่วงหน้าที่คำตอบมีประโยชน์ต้องเปลี่ยนโพรงหรือผิวในแบบที่ fixed template ทำไม่ได้ แต่ไม่จำกัดคำตอบให้เป็นรูปทรงเป้าหมายที่วาดไว้ และมีโจทย์ที่ fixed family แข่งขันได้ด้วย เพื่อไม่สร้าง benchmark ที่เข้าข้าง representation ใหม่อย่างเดียว

## 6. ความสอดคล้องของมวล เรขาคณิต และหลายระดับความละเอียด

ใช้หน่วย SI และบัญชีการเป็นเจ้าของเนื้อวัสดุทางกายภาพร่วมชุดเดียว สำหรับแต่ละบริเวณ คำนวณมวลจากอินทิกรัลความหนาแน่นในปริมาตรที่มีเนื้อ หา center of mass และ inertia tensor เต็มในกรอบพิกัดที่ประกาศ การรวมชุดประกอบต้องนับแต่ละบริเวณครั้งเดียว พร้อมแปลงกรอบและใช้ส่วนจากทฤษฎีแกนขนานอย่างถูกต้อง บริเวณหลายหน้าที่ไม่ถูกคิดมวลซ้ำ และ CAD bodies ที่ตัดกันต้องไม่กลายเป็นเนื้อวัสดุซ้อนกันอย่างเงียบ ๆ

เทียบปริมาตร/มวลของ CAD, ผิว tessellation, volume mesh และแบบลดรูป บันทึกความต่าง ความคลาดเคลื่อนประมาณเรขาคณิต และ tolerance รับได้ การรวมปริมาตรสมาชิกแท่งไม่ได้เท่ากับปริมาตรของเนื้อ union ที่มี junction เชื่อมมนโดยอัตโนมัติ เรขาคณิตชน โครงสร้าง พื้นที่ถ่ายเทความร้อน และช่องของไหลต้องอ้างอิง revision และสถานะประกอบเดียวกัน

รายละเอียดเรขาคณิตกับ fidelity การจำลองเป็นคนละแกน:

| สถานะเรขาคณิต | ความหมาย |
|---|---|
| `G0` | ปริมาตรแนวคิดและรายละเอียดภายในที่ประกาศว่ายังไม่ทราบ ใช้เชิงสำรวจเท่านั้น |
| `G1` | เนื้อวัสดุที่ทำหน้าที่และรอยต่อประกอบครบสำหรับ subsystem ที่ประกาศ |
| `G2` | เรขาคณิตภายในที่จำเป็น รายละเอียดการยึด/contact, tolerance และบัญชีมวลครบ |
| `G3` | เรขาคณิตชุดประกอบทั้ง candidate และส่งต่อการผลิต โดยไม่มีฮาร์ดแวร์จำเป็นที่อธิบายไม่ได้ |

เป็นป้ายใหม่ที่เสนอในแผน ไม่ใช่สถานะที่พัฒนาแล้ว และไม่แทนสถานะหลักฐานแยกมิติจาก Work 104 โมเดล `G3` ยังอาจไม่ได้รับการยืนยันทางฟิสิกส์

ไม่แก้ contact ทุกหน้าเกลียวในทุก time step ของรถ ให้แก้การตอบสนองข้อต่อแบบละเอียดในช่วงโหลด/อุณหภูมิ/preload ที่ลงทะเบียน ลดรูปพร้อมระบุความคลาดเคลื่อน แล้วใช้แบบนั้นในรถ ถ้ารถออกนอกช่วงต้องหยุดอาศัยแบบลดรูปนั้นและเพิ่มความละเอียด/ประเมินใหม่ ถ่ายโอนแรง โมเมนต์ ความร้อน และการกระจัดให้สอดคล้องกัน รวมการตรวจพลังงานที่ส่งผ่าน รายละเอียดเต็มยังต้องมีในเรขาคณิตขั้นสุดท้ายตามความจำเป็น แม้ runtime จะใช้แบบลดรูปที่ตรวจสอบแล้ว

## 7. กรณีพิสูจน์ระดับการยึดชิ้นส่วน

การสาธิตชุดประกอบละเอียดครั้งแรกควรเป็นจุดเชื่อมถ่ายแรงขนาดเล็ก ไม่ใช่รถอีกคันที่แค่ดูเหมือนครบ ใช้ข้อต่อเกลียวที่คุ้นเคยเป็น reference ตรวจความถูกต้องเท่านั้น ทางเลือกที่ระบบสร้างอาจมีเกลียว ไม่มีเกลียว หรือรวมเป็นเนื้อเดียวก็ได้

โจทย์ที่ล็อกไว้ระบุ terminals, ประวัติแรง/โมเมนต์, การเคลื่อนที่ที่ยอมได้, envelope, ช่วงอุณหภูมิ, หลักฐานวัสดุ/กระบวนการที่อนุญาต และเงื่อนไขประกอบ ค้นหาเนื้อวัสดุ ช่องว่าง ตำแหน่งรอยต่อ และวิธีเชื่อมระหว่างนั้น ความสำเร็จคือเชื่อมและทำหน้าที่ได้ภายใต้เงื่อนไขเหล่านี้ ไม่ใช่หน้าตาคล้ายน็อต

ต้องมีหลักฐานระยะขบ/clearance, การตั้ง preload หรือ constraint เริ่มต้นแบบอื่น, สมดุลแรง/โมเมนต์แบบ vector, contact เปิด/ลื่น, การเสียรูป/ความเค้นเฉพาะจุด, ผลความร้อนเมื่อเกี่ยวข้อง และขอบเขตความเสียหาย ถ้าใช้ torque สร้าง preload ต้องรวมความไม่แน่นอนแรงเสียดทาน ไม่ใช้สูตร torque-to-force แน่นอนสากล อ้างการคลายตัวและความล้าได้เมื่อมีแบบจำลองและข้อมูลที่ใช้กับกรณีนั้น มิฉะนั้นคงสถานะ unresolved

กรณีพยายามหักล้าง: เอาข้อต่อออก ตัดเนื้อวัสดุที่รับแรง กลับทิศ/เยื้องแกนแรง เปลี่ยนระยะขบหรือรากเกลียว ใส่ clearance/tolerance สุดช่วง และออกนอกช่วงที่แบบลดรูปผ่านการตรวจ เส้นทางทางกายภาพที่ทำนายต้องตอบสนองตามเหตุ candidate ที่ขาดการเชื่อมอาจเสียหายหรือเคลื่อนที่อิสระ แต่ต้องไม่ถูกช่วยด้วย support ที่แต่งขึ้น

ส่งมอบ geometry ละเอียด ภาพแยกประกอบ/หน้าตัด สถานะประกอบ material map, mesh, fields, convergence, การเทียบมวล และการเทียบแบบหยาบ การตรวจภาพช่วยทบทวนเรขาคณิต แต่ไม่ใช่การยืนยันโครงสร้าง

## 8. ลำดับความสามารถฟิสิกส์

เปิดใช้เฉพาะโดเมนที่มีแบบจำลองและ dependency รองรับจริง เทคโนโลยีนอกกฎ constitutive ที่มีอยู่ยังเป็นแนววิจัย unresolved ไม่ใช่ฟิสิกส์ที่ห้ามใช้

| โดเมน | เป้าหมายที่เรขาคณิตต้องมีผลจริง | การตรวจสอบก่อนอ้างใช้ในการออกแบบ |
|---|---|---|
| กลศาสตร์ของแข็ง | การกระจัด/ความเค้นแบบ vector ผิวและ support จริง | rigid-body modes, patch/reference tests, residual แรง/โมเมนต์/พลังงาน, refinement อย่างน้อย 3 ระดับ และ reference อิสระ |
| ข้อต่อและ contact | แยกตัว ลื่น เสียดทาน preload และ compliance | contact ฝ่ายเดียวและขีดจำกัด friction, reaction ที่แก้คืนได้, บัญชีพลังงาน และ refinement ของ contact/time step |
| การเคลื่อนที่ | rigid/flexible multibody dynamics และ contact ที่เปลี่ยนตามเวลา | constraint สอดคล้อง การเคลื่อนอิสระ ตรวจโมเมนตัม/พลังงาน และทดสอบ event/กลับทิศ |
| ความร้อน | conduction ตามเวลา รอยต่อและแหล่งความร้อนจริง | สมดุลความร้อน time/space refinement และกฎขึ้นกับอุณหภูมิเมื่อใช้ |
| Thermo-mechanics ที่เชื่อมโยง | อุณหภูมิเปลี่ยนมิติ/preload/วัสดุ ส่วนความสูญเสียเปลี่ยนอุณหภูมิ | ทดสอบ coupling สองทางที่ไม่เป็นศูนย์ และเทียบ control ที่ปิด coupling |
| ความเสียหายวัสดุ | plasticity, buckling, fatigue, fracture, wear ตามที่เกี่ยวข้อง | ข้อมูลวัสดุที่ใช้ได้จริง ความไวต่อ imperfection/ประวัติ และระบุ failure modes ที่ยังละไว้ |
| ของไหล/อากาศ | เรขาคณิตทางไหลภายในและการไหลภายนอก | บัญชีมวล/โมเมนตัม/พลังงาน ความไวขอบเขต/mesh/time และ reference/การวัดอิสระ |
| พลังงานและ actuation | เก็บ/แปลง/ส่งพลังงานพร้อม containment และความสูญเสีย | กฎอนุรักษ์ตามโดเมน ขีดจำกัด capacity/rate/temperature มวลฮาร์ดแวร์และขอบเขตเสียหาย |
| การควบคุมและรับรู้ | hardware authority, power, latency, noise และ mounting ที่มีขีดจำกัด | เส้นทางสัญญาณ/actuation มีเหตุจริง saturation, delay, faults และต้นทุนปรับ controller |

ถ้าเลือก electromagnetic, electrochemical, combustion หรือเส้นทางอื่น ต้องมีสายกฎ constitutive และการตรวจสอบของเส้นทางนั้น ค่า efficiency ทั่วไปค่าเดียวพิสูจน์ไม่ได้ว่าฮาร์ดแวร์ภายในมีอยู่จริง เริ่มจาก reference route ที่ทำได้และมีเอกสารรองรับเพื่อฝึกการรวมระบบ ระบุข้อจำกัดของ trial นั้น และรักษา interface ให้ต่อเส้นทางอื่นได้ นี่เป็นการเลือกช่วงพัฒนา ไม่ใช่ whitelist เทคโนโลยีถาวร

ทุก solve ต้องบันทึก reactions ที่คำนวณคืนได้ งาน/ความร้อน/พลังงานผ่านขอบเขต numerical failures, conditioning/quality diagnostics, error bounds และโดเมนที่ขาด residual ที่สร้างให้เท่ากับแรงป้อนตามนิยามไม่ใช่การตรวจอนุรักษ์อิสระ ความเค้นเอกฐานที่มุมคมอุดมคติต้องระบุวิธี regularization หรือ quantity of interest ไม่อ้างว่าความเค้นจุดนั้น mesh-converged ด้วยการแอบเฉลี่ยทิ้ง

## 9. วงค้นหา: รถและชิ้นส่วนวิวัฒน์ร่วมกัน

วงทำงานคือ:

```text
Frozen external task and evidence rules
  -> architecture + spatial material proposal + controller proposal
  -> candidate-derived interface/load envelopes
  -> detailed part/connection generation and local evaluation
  -> exploratory coupled assembly and vehicle evaluation
  -> revised loads, packaging, heat, energy, failure and control requirements
  -> mutate architecture AND parts; retain bounded useful hypotheses
  -> evidence promotion only for the actual declared use conditions
```

ความหมายของวงข้างต้นคือ ล็อกโจทย์ภายนอกและกติกาหลักฐาน เสนอสถาปัตยกรรม/เนื้อวัสดุ/การควบคุม หาโหลดและรอยต่อจาก candidate สร้างและประเมินชิ้นส่วนละเอียด ทดลองชุดประกอบและรถแบบเชื่อมโยง แล้วนำโหลด พื้นที่ ความร้อน พลังงาน ความเสียหาย และเงื่อนไขควบคุมที่พบกลับไปแก้ทั้งสถาปัตยกรรมกับชิ้นส่วน เลื่อนระดับหลักฐานได้เฉพาะเงื่อนไขใช้งานที่พิสูจน์จริง

โจทย์ย่อยเป็นสมมติฐานมี version ไม่ใช่การแบ่งระบบโดยมนุษย์ที่ตรึงถาวร บริเวณหนึ่งอาจรับแรง ส่งกำลัง และระบายความร้อนพร้อมกัน ต้องประเมินปฏิสัมพันธ์และนับวัสดุครั้งเดียว ข้อเสนอสถาปัตยกรรมอาจลบรอยต่อด้วยการรวมเนื้อ หรือเพิ่มรอยต่อเพื่อให้เคลื่อนที่/ประกอบได้

feedback จากรถช่วงต้นใช้แบบลดรูป ช่วงค่าชั่วคราว และโดเมน unresolved ที่ระบุชัดได้ แต่ห้ามแต่ง coefficient ที่เข้าข้างสำหรับระบบที่ขาด ถ้าช่วงค่าทำให้ตัดสินไม่ได้ ให้รายงานและจัดงานประเมิน/เพิ่มความละเอียด การทดลอง coupled ครั้งแรกควรเกิดหลังมี fields และ interfaces พื้นฐาน ไม่ต้องรอพัฒนาเทคโนโลยีพลังงานทุกแบบก่อน

ใช้การปรับ geometry/material เฉพาะที่เมื่ออนุพันธ์มีความหมาย ใช้ topology/program mutations เมื่อไม่มี และเก็บ archive หลากหลายแทนบังคับ optimizer เดียว เก็บ feasible, near-feasible และ unresolved ที่ให้ข้อมูลภายใต้เพดานที่ลงทะเบียน ความแปลกตาหรือกราฟเปลี่ยนข้าม feasibility ไม่ได้ และ topology คงเดิมก็ต้องไม่ปิดกั้นการปรับปรุงจริงที่แยกจากความไม่แน่นอนได้

เปรียบเทียบการแทนชิ้นส่วนทั้งภายใต้ controller ร่วมและการปรับ controller ด้วยต้นทุนเท่ากัน หาโหลดของแต่ละ candidate ด้วยกติกาโจทย์ภายนอกเดียวกัน แล้วตรวจหลักฐานชิ้นส่วนใหม่เมื่อ feedback จากรถเปลี่ยนช่วงการใช้งาน

## 10. ระบบหลักฐานและทรัพยากร

ผูกตัวตน input ตลอดสาย: task, candidate, CAD/material field, mesh, material data, contact laws, solver/version/settings, controller, environment, random seed, admission decisions และ source artifacts ตรวจหลักฐานต้นทางที่นำมาใช้ ไม่ตรวจเพียง summary ที่บอกว่าผ่านแล้ว ข้อมูลย้อนหลังที่เคยเห็นเปลี่ยนชื่อแล้วกลายเป็น holdout ใหม่ไม่ได้

จองงบก่อนเริ่มคำนวณ คิดต้นทุน CAD/mesh/solver ที่ล้มเหลวและการลองซ้ำ และเก็บข้อเสนอที่หยุดหรือยังไม่ได้ประเมิน บันทึก wall time, CPU/GPU ที่วัดได้เมื่อมี, hardware, concurrency, mesh/DOF, iterations, cache use และ peak memory การวัดที่ไม่ทราบไม่ใช่ต้นทุนศูนย์ รวม search, controller tuning, audits และ final validation ในงบที่ใช้เทียบกัน

ก่อนเปรียบเทียบ ล็อกหน่วยทรัพยากร งบรวม และส่วนแบ่ง broad search, การสุ่ม audit representation ที่ไม่ขึ้นกับคะแนน, quality promotion, การเพิ่มระดับ unresolved และ finalists ใช้ pilot แยกเพื่อกำหนดจำนวนและ tolerance ที่ทำไหว ไม่แต่ง seed count สากลหรือ runtime รถทั้งคันตอนนี้ บันทึกการเปลี่ยนเป็น registration ใหม่ ไม่เขียนผลเก่าทับ

รายงาน coverage การประเมินแยกตาม representation และ audit false negatives ถ้ารูปทรงไม่คุ้นเคย mesh ไม่ผ่านมากผิดสัดส่วน ให้ตรวจ adapter ก่อนสรุปว่ารูปทรงเหล่านั้นแย่ทางฟิสิกส์ แยก exact decision replay จาก execution replay ที่ใช้ tolerance ของ floating point

## 12. หมุดหมาย: วัดผลลัพธ์ ไม่ใช่จำนวนเอกสาร

### M1 — เรขาคณิตเนื้อวัสดุไม่คุ้นเคยทำให้สนามฟิสิกส์เปลี่ยนและตรวจสอบได้

ทำความสามารถใน Works 107–110 ให้ได้ รูปทรงที่ระบบสร้างซึ่งไม่สมมาตร/โค้ง/มีโพรงถูก mesh จาก geometry จริง และเมื่อเปลี่ยนรูปทรงทำให้ vector structural response เปลี่ยน รูปทรงที่ topology เดิมมีสิทธิ์ผ่าน รายงาน geometric error แยกจาก discretization error นี่คือความก้าวหน้าวิศวกรรมสำคัญแรก ไม่ใช่ป้าย vehicle-ready ใหม่

### M2 — จุดเชื่อมละเอียดและชุดประกอบเล็กที่เชื่อมโยงระบบ

ทำ Works 111–116 ที่เกี่ยวข้อง แสดงจุดเชื่อมจริงละเอียดถึงระดับการยึด พฤติกรรม moving/contact เมื่อจำเป็น และกรณี feedback thermal/mechanical หรือ architecture/part แบบ coupled มีภาพหน้าตัด geometry ภายใน และ causal negative controls ยังเป็นหลักฐาน subsystem ไม่ใช่รถครบคัน

### M3 — Candidate รถดิจิทัลครบรายละเอียด

ทำ domain packages ที่จำเป็นและ Works 122–125 ให้ครบ ทำเส้นทางทางกายภาพที่จำเป็นให้เกิดจริง ไม่ต้องทำเทคโนโลยีที่เป็นไปได้ทุกชนิด แสดงชุดประกอบ ชิ้นส่วนภายใน บัญชีบริเวณวัสดุ การตรวจ motion/clearance, mass/inertia จาก geometry และ coupled simulation พร้อม uncertainty ชัดเจน ถ้าฟิสิกส์สำคัญ unresolved ให้เรียก detailed exploratory candidate ไม่ใช่รถที่เลื่อนระดับแล้ว

### M4 — คำกล่าวอ้างการค้นพบที่มีหลักฐานรองรับ

ทำ Works 126–129 สำหรับคำกล่าวอ้างนั้น แสดงประโยชน์ระดับรถที่ทนทานและมากกว่า numerical uncertainty เมื่อเทียบ baseline ที่ปรับให้ดีอย่างเป็นธรรม และมี analysis อิสระ ผลเปรียบเทียบลบเป็นหลักฐานที่มีประโยชน์ แต่ยังไม่บรรลุหมุดหมายค้นพบด้านสมรรถนะ ความใหม่ภายนอกต้องมีการสำรวจ prior art แยก รูปทรงแปลกอย่างเดียวพิสูจน์ไม่ได้

### M5 — ตรวจสอบทางกายภาพในขอบเขตที่ค่อย ๆ ใหญ่ขึ้น

ทำ Works 130–132 เมื่อได้รับอนุญาต Numerical convergence และ solver อิสระเพิ่มความมั่นใจแต่แทนการวัดไม่ได้ แยกหลักฐาน calibration ออกจาก validation ชิ้นทดสอบวัสดุผ่านไม่ได้รับรองรถทั้งคัน และไม่มี roadmap ใดรับประกันการค้นพบเทคโนโลยีแข่งใหม่หรือชนะรถแข่งที่มีอยู่

- `src/formula_ultimate/components/spatial_material_cad.py`: adapter จาก free-form B-rep ที่มีอยู่และการวัดอิสระ
- `config/cad/spatial_material_corpus_v1.json`: positive/negative geometry cases ที่ล็อก
- `scripts/cad/run_spatial_material_corpus.py`: build, inspect, บันทึก provenance และ replay
- `tests/test_spatial_material.py` และ `tests/test_spatial_material_cad.py`: แยก pure-contract tests จาก actual-CAD tests ชัดเจน
- `docs/contracts/SPATIAL_MATERIAL_V1.md` และคู่ภาษาไทย พร้อมบันทึกงานสองภาษาใหม่

contract fields ที่เสนอ: `schema_version`, `candidate_id`, `revision`, `units`, `frames`, `material_regions`, `void_regions`, `interfaces`, `geometry_source`, `material_source`, `tolerances`, `evidence_refs` เป็นชื่อที่วางแผน ไม่ใช่ fields ที่โค้ดรองรับแล้ว

corpus แรกต้องทดสอบหน้าตัดแปรผันแบบโค้ง โพรงไม่สมมาตร บริเวณแตกแขนง/รวม บริเวณหลายวัสดุที่สัมผัสกัน และ bodies แยกที่ประกาศไว้ สิ่งเหล่านี้เป็น contract tests ไม่ใช่รูปทรงที่อนุญาตเพียงชุดเดียว Negative controls รวมเนื้อซ้อนที่ไม่ประกาศ โพรงหายตอน export เรขาคณิต non-finite ไม่มีที่มาวัสดุ การนับเนื้อซ้ำ และใช้หลักฐานเก่าหลัง mutation อนุญาต reference cases วัสดุเนื้อเดียวเพื่อทดสอบเครื่องมือคำนวณ mass properties

ผลรันที่ต้องได้: นิยาม candidate, geometry export จริง, material/void manifest, mass/center-of-mass/inertia measurements, การเทียบ CAD อิสระ, discrepancy report, source hashes และ replay report การเปลี่ยนโพรงหรือวัสดุแบบควบคุมต้องเปลี่ยนปริมาณฟิสิกส์ที่ควรเปลี่ยน การย้ายตำแหน่งแบบ rigid ต้องแปลง inertia ถูกโดยไม่เปลี่ยนมวลเนื้อแท้

ก่อน admitted execution ใช้ pilot ที่เปิดเผยเพื่อกำหนด tolerance ความยาว/ปริมาตร/มวล/inertia ตามพฤติกรรม kernel และ feature เล็กสุดที่ตั้งใจใช้ บันทึกตัวเลขในแผน/config ของ Work 107 ก่อนเปรียบเทียบ ความสำเร็จต้องให้ positive cases ทุกกรณีรักษา invariant ที่ประกาศ negative cases ทุกกรณี fail ให้เห็นด้วยสาเหตุที่ตั้งใจ และ replay ตรงกติกา identity แบบ exact/toleranced ที่ลงทะเบียน ห้ามลดเกณฑ์หลังเห็น admitted failure

ชั้น validation: pure Python schema/math tests; สร้าง/export CAD จริง; ตรวจ geometry อิสระ; mutation-causality tests; unit/frame invariance; deterministic provenance; ตรวจเอกสารสองภาษา ต้องรัน CAD-dependent tests จริงใน CAD environment ก่อนอ้างว่า adapter ใช้ได้ test ที่ skip เพราะ dependency ไม่พร้อมไม่ใช่การผ่าน exit gate นี้

สิ่งที่ไม่ทำ: implicit solver สากลใหม่ เกลียวทุกรูปแบบ nonlinear contact, whole-vehicle simulation หรือการชนะเชิงค้นพบ สิ่งส่งต่อ Work 108/109 คือ input geometry/material ที่เชื่อถือได้ ไม่ใช่ชิ้นส่วนที่ยืนยันทางฟิสิกส์แล้ว แก้บั๊กโค้ดเดิมเฉพาะที่ขวาง contract นี้และบันทึกขอบเขตชัดเจน ส่วนการแก้ intake/accounting อื่นจัดไว้กับ package อนาคตที่รับผิดชอบ

## 14. การออกแบบการทดลองและการพยายามหักล้าง

ทุก admitted study ต้องลงทะเบียนรายการต่อไปนี้ เลือกตัวเลขด้วย calibration แยกและล็อกก่อนผล:

| รายการ | การศึกษาชิ้นส่วนละเอียด | การศึกษารถทั้งคัน |
|---|---|---|
| ตัวแปรต้น | representation, การเปลี่ยน material/void, วิธีเชื่อม, topology, optimizer/fidelity policy | architecture, part variants, interaction paths, controller policy และ fidelity policy |
| ตัวแปรตาม | mass, compliance, losses, capacity, thermal response, failure margins, compute cost | race completion/time, primary energy, thermal/structural margins, robustness และต้นทุน search/validation ทั้งหมด |
| ตัวควบคุม | terminal task, สมมติฐานวัสดุ/กระบวนการ, seed pairing, งบรวมเหมือนกัน, fixed family ที่ปรับดี และ random search | กติกา race/environment/energy ภายนอกเดียวกัน โอกาสใช้ library, optimized baseline และทรัพยากรปรับ controller |
| การแทรกแซงทดสอบเหตุ | เอาออก/ตัด/ต่อทางใหม่ เปลี่ยนผิวที่ทำงาน ปิด coupling แทน shape ที่ topology เดิม | สลับ subsystem เดียว ใช้ controller เดิมเทียบปรับใหม่ รวมการเปลี่ยน cooling/support/containment ปิดกลไกที่เสนอ |
| สำเร็จ | ผลมีประโยชน์ตามที่ลงทะเบียนมากกว่า numerical/measurement uncertainty และผ่าน constraints ในขอบเขต | ประโยชน์ทั้งระบบที่ลงทะเบียนยังอยู่หลัง fair comparison, holdout, uncertainty และ independent checks |
| ล้มเหลว | ประโยชน์หายเมื่อใช้ geometry-derived fields, ใช้ช่องโหว่แบบหยาบ หรือ cost/constraints ทำให้เปรียบเทียบไม่ได้ | แข่งไม่จบ ประโยชน์ย้ายไปซ่อนใน hardware/energy ที่ละไว้ ละเมิด failure margins, holdout หรือฟิสิกส์เข้มขึ้นขัดแย้งคำอ้าง |

แยกผลดีขึ้น แย่ลง และแยกไม่ออก แปลง error estimates ให้เป็นหน่วยเดียวกับปริมาณที่เทียบก่อนวัด detectability; error ที่สัมพันธ์กันต้องใช้วิธีเปรียบเทียบเหมาะสม ห้ามใช้ absolute response difference แทน signed improvement

ทำ audits ที่ไม่ขึ้นกับคะแนนสำหรับ candidate ที่ตัวประเมินหยาบปฏิเสธ แยก physical infeasibility จาก meshing/solver failure และข้อเสนอที่ไม่ได้ประเมิน ใช้ implementation คณิตศาสตร์เดียวกันหุ้ม wrapper สองตัวไม่ใช่ reference ฟิสิกส์อิสระ ตรวจที่มา holdout ปัจจุบันก่อน scientific comparison ใหม่ เงื่อนไขที่เคยตรวจแล้วคงเป็น calibration/exploratory evidence

ทุกผลต้องมีหลักฐานสนับสนุน หลักฐานขัดแย้ง คำอธิบายทางเลือก หลักฐานที่ขาด และความมั่นใจ candidate ล้มเหลวเป็นผลทดลองที่ถูกต้องได้ การผ่าน software tests ไม่ทำให้สมมติฐานวิทยาศาสตร์จริง

## 15. วิธีจัดงบคำนวณและลำดับเวลาที่ทำได้จริง

ไม่สัญญาวันเสร็จจากจำนวน work IDs ที่เหลือ ทำ cost pilots ทุกครั้งที่เพิ่มสเกล geometry/physics วัดคอขวด และปรับแผนดำเนินงานอย่างโปร่งใส work ID คือชิ้นงานขอบเขตชัด ไม่ใช่จำนวนชั่วโมงตายตัว

ใช้ coarse-to-fine screening, local submodels และแบบลดรูปที่ตรวจแล้ว cache ได้เฉพาะเมื่อ causal input identities และ validity envelopes ตรง ใช้โครงสร้าง sparse/local และ warm starts พร้อมบันทึกต้นทุน ห้ามแปลง solver non-convergence เป็นคะแนนดีผิดจริง จัดการจำลองละเอียดให้การตัดสินที่ไวต่อ uncertainty และสุ่ม audit representation ไม่คุ้นเคยโดยไม่ขึ้นกับคะแนน

ไม่เริ่มจาก whole-car mesh ที่แก้ทุกเกลียวเล็กและทุกสเกลของไหลตามเวลาพร้อมกัน แบ่งตามปฏิสัมพันธ์ฟิสิกส์และถ่ายโอนปริมาณพร้อม residual checks เพิ่มความละเอียดเฉพาะบริเวณสำคัญ โดยยังเก็บ geometry ครบและแสดง reduction error ถ้างบคำนวณแยกกลไกชี้ขาดไม่ได้ ให้รายงาน comparison unresolved แทนประกาศผู้ชนะ

ทุก milestone รายงานความคืบหน้าจากหน้าที่ที่เกิดจริง geometry coverage, โดเมนที่ตรวจแล้ว, ขอบเขตใช้แบบจำลอง, เส้นทางทางกายภาพที่ครบ และ wall-time-to-evidence ไม่รายงานเปอร์เซ็นต์เสร็จจากจำนวนเอกสาร operators หรือ tests ที่ผ่านเพียงอย่างเดียว

## 16. ความเสี่ยง เงื่อนไขหยุด และการกู้ความก้าวหน้า

| ความเสี่ยงหรือสิ่งที่พบ | สิ่งที่ต้องทำ |
|---|---|
| CAD kernel ปฏิเสธรูปทรงไม่คุ้นเคยที่อาจเป็นไปได้ | เก็บ proposal และ diagnostics ปรับ representation/export และ audit อคติ ไม่อ้างว่าเป็นไปไม่ได้ทางฟิสิกส์ |
| mesh หรือ solver ล้มเหลวกับ geometry บาง/เรียว/contact | จัด unresolved ตรวจ quality, scaling และ formulation ที่ขาด ไม่ซ่อม geometry ลับหรือเติม support สมมติ |
| ประโยชน์เฉพาะชิ้นหายตอนประกอบ | บันทึกหลักฐานลบ แก้คู่ architecture/part และหาโหลดใหม่ ไม่ซ่อนมวลหรือความร้อนที่โยกไป |
| ความใหม่ที่เห็นเป็นส่วนยื่นไม่ทำงาน | ทำ causal ablation ไม่นับส่วนที่ไม่ทำงานเป็น functional novelty แต่เก็บ provenance |
| กราฟเดิมมีผลที่เป็นประโยชน์จาก shape | เปิดให้วิเคราะห์ function/performance ไม่บังคับกราฟเปลี่ยน |
| optimizer ใช้ช่องโหว่ฟิสิกส์/ขีดจำกัดวัสดุที่ละไว้ | บล็อกคำอ้างสูงขึ้น เพิ่มงาน evaluator/coverage และ registration ใหม่ เก็บช่องโหว่เป็น regression case |
| บัญชีต้นทุนหรือที่มาหลักฐานไม่ครบ | บล็อก fairness/admission claims ไม่ใส่ศูนย์แทนค่าที่ไม่ทราบย้อนหลัง |
| การทดลองจริงไม่ปลอดภัยหรือไม่ได้รับอนุญาต | หยุดช่วงทดสอบนั้น เก็บงานดิจิทัลไว้ และขออำนาจ/การทบทวนสถานที่ที่จำเป็น |

## 17. ขอบเขตเครื่องมือและแหล่งต้นทาง

ใช้ CAD stack เดิมต่อเมื่อพฤติกรรมที่วัดได้เพียงพอ ประเมิน backend meshing/solver/coupling ที่เป็นตัวเลือกด้วย fixtures ใน roadmap, reproducibility, ความพร้อมบน Windows, licensing, การตรวจภายใน และต้นทุนที่วัด ก่อนเลือกหรือติดตั้ง Work 106 ไม่เลือกหรือติดตั้ง backend ใด

แนวทางโครงสร้างพื้นฐานที่เป็นไปได้ ตรวจเอกสารต้นทางเมื่อ 2026-09-07:

- Gmsh ระบุ model entities แบบ OpenCASCADE/discrete และ mesh-size fields จึงเป็นตัวเลือกสำหรับ geometry-to-mesh adapter ไม่ใช่หลักฐานว่า repository นี้มี adapter แล้ว [Gmsh reference manual](https://gmsh.info/doc/texinfo/gmsh.html)
- MFEM มีตัวอย่าง finite-element รวม linear และ nonlinear elasticity ใช้ประกอบการตรวจความถูกต้องและทดลอง backend ได้ แต่ไม่ได้ยืนยัน contact, materials หรือรถของโครงการนี้ [MFEM examples](https://mfem.org/examples/)
- OpenMDAO มีเอกสาร coupled multidisciplinary analysis/optimization framework ลักษณะนี้อาจจัดระบบ solvers และ derivatives แต่ไม่ได้เติมแบบจำลองฟิสิกส์ที่ขาดหรือทำให้ topology mutations กลายเป็นตัวแปรเรียบต่อเนื่อง [OpenMDAO documentation](https://openmdao.org/newdocs/versions/latest/)

representation การออกแบบหลายสเกล และลำดับส่งมอบในเอกสารนี้เป็นข้อเสนอของโครงการ ไม่ใช่คำอ้างที่พิสูจน์จากคู่มือภายนอกเหล่านั้น การพัฒนาวิธีเฉพาะในอนาคตต้องทบทวนแหล่งอ้างอิงและมีแผนตรวจสอบของตนเอง

## 18. Checklist รับงานปลายทาง

บรรลุจุดหมายดิจิทัลละเอียดเมื่อ candidate ทั้งคันที่เลือกมีครบดังนี้:

- เรขาคณิตทางกายภาพที่ต้องมี อุปกรณ์ภายใน และรายละเอียดการเชื่อมครบ ตรวจได้ทั้งตอนประกอบและผ่าหน้าตัด
- บริเวณวัสดุและเส้นทางหน้าที่จริงที่ย้อนที่มาได้ ไม่มีฮาร์ดแวร์ไร้คำอธิบาย เนื้อวัสดุนับซ้ำ หรือทรัพยากรอุดมคติฟรี
- หลักฐาน mass/inertia, packaging, motion/contact, structure, thermal และ flow/energy/control ที่เกี่ยวข้อง มาจาก geometry
- coupled simulation ผูกกับ geometry revision นั้นจริง พร้อม numerical/model uncertainty ที่ประกาศ
- หลักฐาน manufacturing/tolerance เหมาะกับระดับความพร้อมที่อ้าง
- fair optimized baseline comparison และหลักฐานพยายามหักล้างสำหรับประโยชน์ที่อ้าง
- คำกล่าวอ้างมีขอบเขตชัด: digital completeness, numerical verification, scientific validation และ physical validation เป็นคนละความสำเร็จ

ทิศทางทันทีจึงไม่ใช่ “สร้างรถหน้าตาคุ้นเคยอีกคันแล้วใส่น็อตเพิ่ม” แต่คือ “ทำให้ประเมินฟิสิกส์จากเนื้อวัสดุเชิงพื้นที่ได้จริง พิสูจน์จุดเชื่อมละเอียด เชื่อมชิ้นส่วนกับสถาปัตยกรรมตั้งแต่ต้น แล้วขยายขอบเขตที่ตรวจแล้วจนทุกเส้นทางจำเป็นของรถครบทั้งคันเกิดขึ้นจริง”
