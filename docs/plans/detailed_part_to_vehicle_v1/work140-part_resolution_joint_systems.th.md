# Work 140: ความละเอียดของชิ้นส่วนและระบบข้อต่อ

Dependencies: Work 092 (ขีดจำกัดของ grammar รูปทรงอิสระ), Work 135 (native detailed vehicle), Work 138 (geometry-general evaluator), Work 139 (การประกอบ)

## 1. ปัญหาที่งานนี้แก้

รถละเอียดปัจจุบันดูเหมือนรายการชิ้นส่วน แต่ยังไม่ได้ถูกโมเดลที่ระดับความละเอียดของชิ้นส่วนจริง ค่าที่วัดจาก `config/development/native_detailed_vehicle_v1.json`

- ทั้ง 48 definition ประกาศ **feature ชิ้นละสามอย่างพอดีทุกชิ้น**
- ขนาดเล็กสุดที่ประกาศในรถทั้งคันคือ `1.5 mm` และค่ากลางของ feature เล็กสุดต่อชิ้นคือ `6.0 mm`
- ตัวยึดเป็นทรงกระบอกล้วนกับหัวทรงกระบอก ไม่มีเกลียว ไม่มีมุมลบ ไม่มีผิวรับแรงกด ไม่มีระยะสวม

ขณะที่ grammar ของ Work 092 อนุญาต feature เล็กสุด `1e-05 m` และ 32 feature ต่อชิ้นอยู่แล้ว ข้อจำกัดจึงอยู่ที่คำประกาศ ไม่ใช่ที่ kernel

ข้อต่อก็บางพอกัน การยึดเป็นเพียงป้ายบอกความสัมพันธ์พ่อลูกพร้อมแกน ไม่ใช่ผิวต่อที่ถูกโมเดล และ Work 138 ประเมินชิ้นส่วนแยกกัน จึงยังไม่เคยมีแรงเดินข้ามข้อต่อเลย

## 2. ผลลัพธ์และขอบเขตข้ออ้าง

การผ่านหมายถึงเพียง `passed_part_resolution_gate` คือ gate ทำงานจริง ทุกชิ้นส่วนและทุกข้อต่อที่เป็นหัวข้อทดสอบมีสถานะที่ลงทะเบียนหนึ่งค่า และ control ทั้งหมดถูกปฏิเสธ คำตัดสินต่อชิ้นส่วนใดแยกจากคำตัดสินต่อการรัน ชิ้นส่วนที่ไม่ผ่านคือข้อค้นพบ ไม่ใช่ความล้มเหลวของงาน

นี่คือ gate ด้านความละเอียดของ geometry และหลักฐานของผิวต่อ ไม่ใช่ promotion ไม่ใช่ความเป็นไปได้ในการผลิต ไม่ใช่เวลาแข่ง และไม่ใช่ physical validation

## 3. ความเป็นกลางทางเทคโนโลยี

แบบจะยึดชิ้นส่วนด้วยวิธีใดก็ได้ gate นี้ไม่เคยบังคับให้ใช้น็อต แต่บังคับว่าเทคโนโลยีที่ประกาศต้องมี geometry ที่วัดได้รองรับ

| เทคโนโลยี | หลักฐานที่ต้องวัดได้ |
| --- | --- |
| `threaded` | ผิวขบเกลียวแบบเกลียวหรือแบบอิสระบนทั้งสองชิ้น ผิวรับแรงกด และระยะสวมอยู่ในช่วงที่ประกาศ |
| `welded` | เนื้อเชื่อมที่เพิ่มเข้ามาที่ผิวต่อ และบริเวณผิวต่อที่ต่อเนื่อง |
| `bonded` | ความหนาชั้นกาวอยู่ในช่วงที่ประกาศ และพื้นที่ซ้อนทับไม่น้อยกว่าค่าต่ำสุดที่ประกาศ |
| `interference` | ระยะสวมที่วัดได้เป็นลบอยู่ในช่วงที่ประกาศ |
| `integral` | เป็น solid ต่อเนื่องชิ้นเดียวข้ามผิวต่อ |

ข้อต่อที่ประกาศแต่วัดผิวต่อไม่ได้จะเป็น `unsupported_joint_evidence` ชิ้นส่วนจะอ้างข้อต่อที่ตัวเองไม่มีในเชิงเรขาคณิตไม่ได้

## 4. Gate ความละเอียด วัดจาก solid ที่สร้างจริง

1. **พื้นความเป็นไปได้ในการผลิต** feature เล็กสุดที่วัดได้ต้องไม่ต่ำกว่า `minimum_feature_m` ชิ้นที่ต่ำกว่านั้นเป็น `unmanufacturable_feature` เพราะเศษบางเฉียบไม่ใช่ความละเอียด
2. **ข้อกำหนดความละเอียด** แต่ละชั้นของชิ้นส่วนประกาศจำนวนหน้า จำนวนหน้าโค้ง และจำนวนสเกลของ feature ที่ต้องมี ชิ้นที่ต่ำกว่าข้อกำหนดเป็น `insufficient_resolution`
3. **ความละเอียดของ mesh** mesh ที่ลงทะเบียนต้องวาง element อย่างน้อย `minimum_elements_across_feature` ตัวพาด feature เล็กสุด ไม่เช่นนั้นชิ้นนั้นเป็น `unresolved_measurement` และห้ามใช้อ้างความแข็งแรงใด

- ข้อต่อครอบคลุมหลายเทคโนโลยี โดยมีอย่างน้อยหนึ่งข้อต่อที่ผ่าน และอย่างน้อยหนึ่งข้อต่อที่มาจาก Work 135

## 7. Control ที่บังคับ

1. ชิ้นที่ feature เล็กสุดต่ำกว่าพื้นต้องถูกปฏิเสธ
2. ชิ้นที่ต่ำกว่าข้อกำหนดความละเอียดต้องถูกปฏิเสธ
3. mesh ที่หยาบเกินกว่าจะพาด feature เล็กสุดต้องได้ `unresolved_measurement` ไม่ใช่ `passed`
4. ข้อต่อที่ประกาศแต่วัดผิวต่อไม่ได้ต้องถูกปฏิเสธ
5. ข้อต่อที่ระยะสวมอยู่นอกช่วงที่ประกาศต้องถูกปฏิเสธ
6. เทคโนโลยีนอกทะเบียนต้องถูกปฏิเสธ
7. การรันต้องไม่อ้างการค้นพบ promotion เวลาแข่ง หรือ physical validation
8. การ replay บน tree ที่สะอาดต้องให้ result SHA-256 ตรงกันทุกประการ

## 8. เกณฑ์การยอมรับ

control ทั้งแปดถูกปฏิเสธ ทุกชิ้นส่วนและข้อต่อที่เป็นหัวข้อมีสถานะที่ลงทะเบียนหนึ่งค่า ทุกตัวเลขของ gate มาจากการวัดไม่ใช่การประกาศ และ replay ตรงทุกประการ

## 9. ความเสี่ยงและการส่งต่อ

- คาดว่ารถปัจจุบันจะไม่ผ่าน ผลนั้นต้องรายงานตามจริง ห้ามทำให้นุ่มลง และห้ามลดมาตรฐานลงเงียบ ๆ
- ข้อจำกัดของ kernel คือหลักฐาน ถ้าสร้างเกลียวหรือ boolean ไม่ได้ ผลคือ `unresolved_measurement` พร้อมข้อความจาก kernel ไม่ใช่การลดรูปชิ้นส่วนอย่างเงียบ ๆ
- การให้แรงเดินข้ามข้อต่อยังต้องใช้การวิเคราะห์แบบ contact หรือ tied surface งานนี้วัดผิวต่อ ยังไม่ได้แก้สมการข้ามข้อต่อ เรื่องนั้นกับการยกรถ Work 135 ทั้งคันขึ้นมาถึงมาตรฐาน เป็นงานถัดไป
